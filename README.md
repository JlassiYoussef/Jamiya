# Jamiya

Jamiya is a multilingual platform for Tunisian associations to manage their administrative and organizational activities in one place.

**Team:** Youssef Jlassi, Khalil Sadem, Azer Nouai, Oumayma Bentaher.
**Course:** CS 488 — AI-First Software Engineering
**Status:** The multilingual dashboard remains a prototype; member records now have a PostgreSQL-backed API, sign-in, and association-scoped role checks.

---

## Project scope

Jamiya is planned as a web platform for multiple associations, with each association's data kept separate. The first release is intended to cover:

- **Authentication and authorization:** account access and role-based permissions for association presidents, administrators, treasurers, members, and volunteers.
- **Association and member management:** association profiles, member records, membership status, and membership dates.
- **Events:** event creation and publication, member registration, and attendance tracking.
- **Volunteers:** volunteer profiles, opportunities, applications, application decisions, and participation tracking.
- **Documents:** upload, organization, access, and retrieval of association documents.
- **Basic financial tracking:** income and expense records with summaries; this is not a full accounting system.
- **Communication:** announcements and in-app notifications.
- **Reports and dashboards:** summaries of association activity and basic financial information.

## Languages

The interface is planned in **Arabic**, **French**, and **English**. Arabic pages will support right-to-left (RTL) layout.

## Architecture and design

The project follows an Agile, iterative approach and an object-oriented design within a layered, three-tier modular monolith:

1. **Presentation:** responsive web interface, using MVC within the UI layer.
2. **Application and business:** authentication, authorization, and services that implement association workflows and rules.
3. **Data access:** repositories that isolate persistence operations from business logic.
4. **Database:** relational persistence, accessed through the data access layer.

Requests flow from the presentation layer through business services and repositories to the database. Only the data access layer communicates with the database. The design uses the **Repository** pattern for persistence and the **Strategy** pattern to keep notification delivery replaceable; the first release uses in-app notifications only. MVC separates the web interface from application logic.

Event registration is coordinated by a registration service. Only members with active membership may register; capacity and duplicate-registration checks must be protected against concurrent requests.

## Outside the current baseline

These features are not planned for the first release, but may be reconsidered later:

- Online payments
- Full accounting
- A native mobile application
- QR-code attendance
- Volunteer certificates
- Email or SMS notifications
- AI features

## Technology and setup

**Selected stack:** React with TypeScript and Vite for the web interface, a NestJS API written in TypeScript, Prisma for data access, and PostgreSQL for relational storage. The workspace uses Node.js 24 LTS and npm workspaces. Frontend tests use Vitest; API tests use Jest. Deployment platform remains undecided.

From `project-starter-template/`, configure PostgreSQL and `.env` using the [setup guide](docs/setup.md), then run `npm ci`, `npm run db:migrate --workspace @jamiya/api`, and `npm run db:seed --workspace @jamiya/api`. The seed values create the first association president account; set a private password in `.env`. Start the web interface with `npm run dev --workspace @jamiya/web` and the API with `npm run start:dev --workspace @jamiya/api`. Run `npm run build`, `npm test`, and `npm run lint` for checks. The API listens on port 3000 by default.
